# Security — threat model and checklist

Living document. Every measure has a status (`done` / `open`) and a reference to the test or file that proves it.
The `security-reviewer` audits against this checklist before every milestone tag.

Status as of v1.2.0 (2026-10-05; full audit since v1.1.0, row C6 added), after ADR-053 (engine process, autosave, updater, release CSP). `done` means the measure holds for the code that exists today and a test or file named in the Evidence column proves it; `partial` means part of it holds and the rest is named; `open` means not done. A new command, plugin or capability must add its own test. Config and capability rows are pinned by `src-tauri/tests/security_baseline.rs`. Historical note: prose in rows T3, T10 and I1 that counts commands or lists the first commands describes the M1 state; the current list of commands and permissions is whatever `security_baseline.rs::capabilities_grant_only_the_app_commands_and_the_window_chrome_to_the_main_window` and `build_script_declares_exactly_the_granted_commands` pin. Section 7 adds the M5 to M7 surfaces; section 8 lists residual risks. Statements marked "unverified" were not proven by a test or run when this was written.

## Threat model

**Attacker:** delivers a malicious PDF (mail, download, USB stick).
**Goals:** code execution via the parser; reading or overwriting local files via IPC or links; exfiltrating document
content; tampering with updates or dependencies.
**Assets:** the user's documents and saved signatures; integrity of the computer.
**Out of scope by design:** there are no accounts and no servers, hence no auth or transport surface. This stays so.

**Added by M5 to M7 (what each new surface lets an attacker try, and what stops it):**

- **Redaction (M5).** A document may promise that text is gone while it is only covered. Redaction rewrites page content, images and annotations, strips metadata when asked, audits the extractable text after the save, and removes the backups of its target (D4). The audit is a text extraction: content it cannot read is not proven gone (R7).
- **Encryption and permissions (M5).** Passwords are session memory only and unlock attempts are serialised (D3). Protection changes are written on save by the Rust side; a restricted document is copied but not changed, and a document that forbids printing or copying is refused by print and export (`tests/protection.rs`, `tests/print_set.rs::a_document_that_forbids_printing_is_refused`, `tests/export_images.rs::a_document_that_forbids_copying_is_not_exported`). Permission flags are advisory in the PDF format; they bind Sheer, not other software.
- **Export and print (M6).** New files are written by jobs the user started with a native dialog or folder pick; names are sanitized (P13), existing files ask first and never write through a link (`tests/export_images.rs::replace_never_writes_through_a_link`), page and byte limits apply (`tests/print_set.rs::a_set_refuses_the_page_and_the_byte_past_the_limits`), print sets expire and are dropped with their document, and the open document is never the target of an export (`tests/export_pdf.rs::the_open_document_is_never_the_target`).
- **Engine process (M7).** PDFium runs in a child of the same executable. A hostile PDF that crashes or wedges the parser costs a restart, not the app or the open work, and the child is distrusted by the parent (P6). The child is not sandboxed (R3).
- **Autosave (M7).** A crash-recovery copy of a dirty document sits in the app data folder as plaintext (never for encrypted documents). It is private to the user by file mode on Unix and by the profile ACL on Windows, bounded in size and age, and cleaned up (D5, R8). An attacker with the user's account can read it.
- **Updater (M7).** The only code that may use the network, opt-in, one HTTPS endpoint, minisign-verified packages, no webview access (T6, S6). Today inactive because the key is a placeholder (B-005). A compromised release channel or a leaked private key is the new way to tamper with the app; the key must stay offline.
- **Release builds.** Unsigned (B-002): a user cannot tell a genuine installer from a replaced one except through `SHA256SUMS.txt` published next to it from the same place (R1).
